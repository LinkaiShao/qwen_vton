# How the eight VTON models actually work

Updated 2026-09-29. This report describes the eight releases in [our detail comparison](README.md), using their papers and the official code revisions used for inference. [Training schedules, datasets and exact checkpoints](model-training.md) are documented separately.

**Follow-up: an explicit warping model is now tested.** [HR-VITON results](../warp-benchmark/README.md) add a ninth model on the same 128 cases. Its convolutional condition network jointly predicts garment flow and segmentation; `grid_sample` explicitly warps cloth RGB, then a SPADE generator consumes the warped cloth, agnostic person and DensePose. Garment transfer uses this flow and convolutional synthesis, rather than the reference-token attention paths in the table below. [Official condition network](https://github.com/sangyun884/HR-VITON/blob/2715bdd687b3a07b8b8bcb3e44aa5533b28c1f15/networks.py), [warp and synthesis](https://github.com/sangyun884/HR-VITON/blob/2715bdd687b3a07b8b8bcb3e44aa5533b28c1f15/test_generator.py#L203-L217).

**They all learn to synthesize the garment on the person. None of these eight inference pipelines first produces an explicitly warped garment with a separate geometric warping network.** Their differences are how they represent the reference garment, how its features enter the generator, and what training encourages those features to preserve. LeFFA does use a garment warp to calculate an auxiliary **training loss**; that is different from a warp-and-paste inference pipeline.

**“Concatenation” and “attention” are compatible operations.** Concatenation assembles the input; attention lets one location read information from another. There are three distinct kinds of concatenation here:

| Operation | What is joined | What it accomplishes |
|---|---|---|
| Spatial canvas concatenation | Person and garment images/latents beside or above each other | One generator processes both regions. CatVTON is the clearest example. |
| Feature-token concatenation | Intermediate person and garment feature sequences inside a layer | Target locations can attend to spatial garment features extracted by another branch. LeFFA is the clearest example. |
| Channel concatenation | Noisy latent, masked-person latent, mask and sometimes pose | Supplies aligned conditions at each target location. This alone does not match a collar on the flatlay to a collar on the person. |

**Architecture comparison**

“Separate garment network” below means an independently parameterized garment UNet, not the VAE that compresses images. “Cross-attention” distinguishes a dedicated conditioning module from cross-image interactions inside joint self-attention.

| Model / backbone | Separate garment network? | Where is concatenation? | What attention actually transfers the garment? |
|---|---|---|---|
| **LeFFA — SD1.5** | **Yes:** a reference UNet, separate from the generative UNet. | At corresponding layers, append reference feature tokens to target feature tokens; retain the target output. | **Joint self-attention** over those tokens. The ordinary text cross-attention modules are removed. Garment features still reach target queries through reference keys/values. [Fusion code](https://github.com/franciszzj/Leffa/blob/05a259104b6927607776c7edb3e86b75406f20aa/leffa/diffusion_model/attention_gen.py#L375-L395), [module setup](https://github.com/franciszzj/Leffa/blob/05a259104b6927607776c7edb3e86b75406f20aa/leffa/model.py#L118-L120). |
| **OOTDiffusion-HD — SD1.5** | **Yes:** an outfitting UNet with its own weights. Its garment pass runs once at fixed timestep zero. | Append garment feature tokens inside each matching self-attention layer; retain the person half. | **Both:** self-attention transfers spatial garment features; cross-attention receives a CLIP garment embedding. [Fusion code](https://github.com/levihsu/OOTDiffusion/blob/13ef0faba266cdde9febc8ad39be2395bbb89d9c/ootd/pipelines_ootd/attention_vton.py#L230-L310), [one-time garment pass](https://github.com/levihsu/OOTDiffusion/blob/13ef0faba266cdde9febc8ad39be2395bbb89d9c/ootd/pipelines_ootd/pipeline_ootd.py#L354-L362). |

Also a CLIP image encoder and IP-Adapter. | GarmentNet and TryonNet feature tokens join inside self-attention. | **Both:** self-attention receives spatial garment features; additional cross-attention receives CLIP/IP-Adapter garment features and garment-caption text. These are different conditioning paths. [Paper, Fig. 2 and §3.2](https://arxiv.org/html/2403.05139v1#S3.SS2). |
| **FastFit-SR — SD1.5** | **No independent garment UNet:** reference and target processing share UNet weights. | Cached garment **K/V tokens** join target K/V tokens during denoising. | **Asymmetric “Semi-Attention”:** target queries read target and reference tokens; each reference reads only itself. Reference features use class embeddings and are cached once. No CLIP/text garment-conditioning path in the evaluated pipeline. [Paper, §4](https://arxiv.org/html/2511.18775v2#S4). |

**How they are trained and conditioned**

The papers start from pretrained generative backbones and train on person/garment pairs. The person wearing the garment supplies the target image. Standard diffusion training samples a timestep and trains a noise or velocity prediction; it does not require a complete sampling rollout for each training example. Auxiliary losses and DREAM can add computation beyond that base forward pass.

| Model | What receives training updates? | Objective / distinctive supervision | Person-side conditions |
|---|---|---|---|
| **LeFFA** | Both UNets. | Noise prediction plus attention-derived flow/warp reconstruction loss. Alignment is restricted to lower-noise timesteps and higher-resolution attention. [Paper](https://arxiv.org/html/2412.08486v2#S3). | Masked person, inpaint mask, DensePose. |
| **OOTDiffusion-HD** | Both UNets, with separate weights. | Noise-prediction MSE; garment dropout supports classifier-free guidance. [Paper](https://arxiv.org/html/2403.01779v1#S3.SS2). | Masked-person latent joins noise. Pose/parsing build the mask; a pose map is not a separate denoiser input. |
| **IDM-VTON** | TryonNet and IP-Adapter. GarmentNet, CLIP encoders and VAE stay frozen. | Denoising supervision, with detailed garment captions. [Paper](https://arxiv.org/html/2403.05139v1#S3.SS2), [freeze settings](https://github.com/yisol/IDM-VTON/blob/0d5f3ec2d737487a9bb24e4100936ad254780383/train_xl.py#L389-L394). | Noisy latent + masked-person latent + mask + DensePose latent: 13 channels. |
| **FastFit-SR** | Shared cacheable UNet design with learned garment-category embeddings; exact trainable subset is not specified in the cited paper. | Noise-predicting diffusion model; asymmetric attention makes reference caching possible. [Paper](https://arxiv.org/html/2508.20586v1#S3). | Masked person composited with DWPose, plus mask. |
| **CatVTON** | Self-attention only: 49.57M parameters. | MSE with DREAM rectification and garment-condition dropout. [Paper](https://arxiv.org/html/2407.15886v2#S3). | Masked person + inpaint mask; no explicit pose-map or text input. |
| **DeCo-VTON** | Full UNet. | Person-panel-only DREAM loss; garment-free unconditional guidance; inference garment latent reset to the clean reference with the scheduled noise. [Paper](https://arxiv.org/html/2511.18775v2#S4). | Same masked person and mask as CatVTON; no explicit pose-map input. |
| **CatVTON-FLUX alpha** | Alpha's exact training recipe is not documented. Public code selects attention parameters despite README wording about full fine-tuning. | Public training code uses flow matching. Its launch settings are not proof of the alpha checkpoint's exact run. [Model card](https://huggingface.co/xiaozaa/catvton-flux-alpha), [parameter selection](https://github.com/nftblackmagic/catvton-flux/blob/59dd165375c94313838c928cae0a9c22a6a25e90/train_flux_inpaint.py#L570-L577). | Person/garment canvas, combined mask, fixed text prompt. |
| **CORAL** | Attention layers. | Velocity prediction + DINOv3 correspondence distillation + attention entropy loss. Teacher matches are filtered for cycle consistency. [Paper](https://arxiv.org/html/2602.17636v1#S4.SS4). | Masked person, mask, DensePose tokens, fixed text prompt. |

Here, **flow matching in FLUX means learning the denoising velocity; it does not mean predicting a geometric cloth-warp field.**

**What “morphing” means in these models**

For a joint-attention layer, a target token reads a weighted combination of value vectors from target and garment tokens. The generator uses those features to draw the garment in the person's pose. This is implicit deformation and synthesis, rather than a deterministic movement of every source pixel. A feature vector can contain texture, shape and contextual information; its spatial index is not a guarantee that it describes only that small source patch.

LeFFA makes an explicit geometric field from attention during training, warps the reference with that field, and measures reconstruction error. The generated image still comes from the denoising UNet and VAE. See [LeFFA's loss definition](https://arxiv.org/html/2412.08486v2#S3.SS2).

The garment-feature branches also differ in time: LeFFA normally runs its reference UNet at the current denoising timestep; OOTDiffusion's runs once at zero; FastFit replaces the reference timestep with a category embedding and caches K/V. LeFFA's code also offers an optional fixed-timestep reference-acceleration mode. [LeFFA pipeline](https://github.com/franciszzj/Leffa/blob/05a259104b6927607776c7edb3e86b75406f20aa/leffa/pipeline.py#L103-L136), [OOTD code](https://github.com/levihsu/OOTDiffusion/blob/13ef0faba266cdde9febc8ad39be2395bbb89d9c/ootd/pipelines_ootd/pipeline_ootd.py#L354-L362), [FastFit paper](https://arxiv.org/html/2508.20586v1#S3.SS3).

**What this implies for our detail-localization idea**

In LeFFA, the relevant readout is the **target-query / garment-key block of joint self-attention**, not a text `attn2` module. In CatVTON it is the interaction between the two canvas regions; in FastFit it is target queries against cached garment keys. Concatenation preserves access to those interactions.

My interpretation: CORAL is the closest of these eight to our proposed localization objective, because it trains the generator's own Q/K matching against external correspondences. Its DINOv3 teacher supplies matches, whereas our existing trained DINOv2 experts score regional similarity. Those roles are different. CORAL also does not establish that every named collar, cuff or button can be located perfectly at every noise level. [CORAL method](https://arxiv.org/html/2602.17636v1#S4.SS4).

Reading one garment-key column asks which target locations attend to it. It does not, by itself, establish a unique destination for that garment point: multiple locations can read the same feature, and attention also supplies contextual appearance. We must validate point transfer separately from image quality.

This report explains the published architectures. Our existing eight-model comparison ran released checkpoints on 128 paired VITON-HD cases; it did not retrain these methods or establish that one architecture caused the observed score differences. The [comparison README](README.md) records the scoring limitations.
